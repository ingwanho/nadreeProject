# 프론트 전달 — 회원 번호 삭제·국제운전면허 필드 확인

2026-11-26 사용자 확정 사항을 반영한 **로컬 구현 완료·서버 적용 전** 계약이다. 요청 원본은 [회원 정책 동의·프로필 번호 연동 요청](../../member-consent-profile-backend-request-2026-11-25.md)이다. 앞서 배포한 회원 동의 시각 기능은 [기존 서버 적용 결과](member-policy-consents-server-verification-2026-11-25.md)를 따른다.

## 확정한 처리 범위

| 요청 | 이번 처리 |
| --- | --- |
| 정책 버전별 동의·현재 문서 주소·재동의 | 이후 추가 작업으로 보류. 기존 회원별 최초 동의 시각 저장은 유지 |
| 프로필 번호 생략 | 해당 번호의 기존 값 유지 |
| 유효한 번호 문자열 전달 | 해당 번호 등록·변경 |
| 프로필 번호를 JSON `null`로 전달 | 해당 회원의 해당 번호만 삭제 |
| `driverLicenseNumber` 의미 | **국제운전면허 번호가 맞다.** 기존 필드명을 그대로 사용 |

문서번호 입력 검증과 고객 본인 인증을 유지하며 빈 문자열·공백만 있는 문자열은 삭제 표현으로 사용하지 않는다. 이번 변경에 별도 삭제 API·새 테이블·컬럼·env는 추가하지 않았다.

## 저장·삭제 API

```http
PATCH /api/v1/nadree/user/profile
Authorization: Bearer <Nadree customer access token>
Content-Type: application/json
```

Firebase ID token으로 로그인한 뒤 받은 Nadree 고객 access token을 사용한다. 본문에 UID를 지정하지 않으며 인증된 본인의 프로필만 수정한다.

여권번호만 삭제하고 국제운전면허 번호는 유지:

```json
{
  "passportNumber": null
}
```

국제운전면허 번호만 삭제하고 여권번호는 유지:

```json
{
  "driverLicenseNumber": null
}
```

두 번호 모두 삭제:

```json
{
  "passportNumber": null,
  "driverLicenseNumber": null
}
```

등록·수정은 기존과 동일하다. 아래 값은 가상 예시다.

```json
{
  "passportNumber": "TEST-PASSPORT",
  "driverLicenseNumber": "TEST-IDP"
}
```

문자열은 1~100자이며 공백이 아닌 문자를 포함해야 한다. 숫자 자료형을 전송하지 않는다. 기존 이름 등 다른 회원정보 수정과 한 요청으로 처리할 수 있다. 유효하지 않은 필드를 함께 보내면 요청 전체가 실패하며 번호만 일부 삭제하지 않는다. 이미 비어 있는 번호를 다시 `null`로 보내도 200이고 빈 값으로 유지한다.

## 조회·응답과 프론트 처리

PATCH 응답과 **GET `/api/v1/nadree/user/profile`**의 `user`에서 확인한다. 재로그인 응답의 `user`에도 반영된다. 아래는 두 번호 삭제 후 추가 관심 필드만 발췌한 가상 응답이다. 기존 회원정보·동의 시각 등 다른 필드도 반환한다.

```json
{
  "status": "success",
  "user": {
    "uidToken": "FIREBASE_CUSTOMER_UID",
    "passportNumber": null,
    "driverLicenseNumber": null
  }
}
```

프론트는 미변경과 삭제 의도를 구분한다. 수정하지 않은 번호는 요청에서 생략하고, 고객이 명시적으로 지운 번호만 JSON `null`로 전송한다. 응답의 `null`은 미입력 또는 삭제된 상태로 표시한다. 문자열 `"null"`은 삭제 표현이 아니므로 전송하지 않는다. 번호 원문은 로그·푸시·분석 이벤트에 남기지 않는다.

`internationalDrivingPermitNumber`로 바꾸거나 두 번호를 별도로 저장할 필요 없이 **`driverLicenseNumber`에 국제운전면허 번호를 전달**한다.

## 인계·매장 조회와의 관계

프로필 삭제는 회원 테이블의 현재 번호만 SQL NULL로 변경한다. 이미 시작한 인계에 기록된 당시 여권·면허번호와 대여 이력은 보존한다. 기존 인계를 소급 수정하거나 완료된 대여 기록을 일괄 삭제하지 않는다.

따라서 매장의 인계·예약/렌트 상세가 해당 인계에 저장된 당시 값을 표시한다면 기존 번호가 계속 보일 수 있다. 회원 프로필의 현재 값과 인계 당시 값의 용도가 다르며, 당시 기록의 추가 삭제·보관 정책은 별도 확정 대상이다. 새 인계는 기존 시작 시점의 회원정보 반영 규칙을 따른다.

**인계 폼에서 선택 면허번호 입력을 취소한 경우에는 해당 필드를 생략한다.** 프로필의 명시적 삭제 요청과 구분하며, 인계 폼의 `null` 전송은 기존처럼 422다. 기존 여권 필수·면허 선택 정책과 인계 폼/서명·렌트 시작 조건은 유지한다.

## 오류·호환성

| 조건 | 응답/처리 |
| --- | --- |
| `passportNumber` 또는 `driverLicenseNumber`의 JSON `null` | 200, 해당 현재 프로필 값 삭제 |
| 번호의 빈 문자열·공백만 있는 문자열·숫자 자료형 | 422 `INVALID_INPUT` |
| 빈 PATCH 객체 또는 이름·나이·성별·국적·FCM·SNS의 명시적 `null` | 422 `EMPTY_PROFILE_UPDATE` |
| 동의 필드의 `false`·`null`·문자열·숫자 | 기존 422 `INVALID_INPUT` |
| 프로필 본문에 다른 UID 등 정의되지 않은 필드 | 422 `INVALID_INPUT` |
| 관리자 토큰 또는 무인증으로 프로필 변경 | 401 `INVALID_NADRI_USER_TOKEN` |

다른 선택 필드의 기본값이 `null`로 표시되더라도 명시적 삭제 허용은 이번 두 번호에만 적용된다. 회원 동의 버전 필드나 새 `/user/legal-consents` 경로는 추가하지 않았다. 현재 동의는 기존 로그인·프로필 API의 명시적 true/최초 서버 시각 계약을 사용한다.

## 검증·서버 적용

관련 격리 검사 **71 passed / 기존 의존성 경고 2개**. 기존 422 차단을 재현한 뒤 번호별 등록·변경·생략·null 삭제·재조회·재로그인·재요청, 다른 번호/동의 시각 보존, 본인 인증·다른 UID 차단·실패 시 부분 삭제 방지와 인계/관리자 조회의 당시 기록 보존을 확인했다. Swagger 입력 설명·번호별 문자열/null 예시와 응답 설명을 갱신했으며 경로/메서드 수는 **105/111**이다.

실제 서버 배포·공유 DB 업무 데이터 변경·실기기 앱 검증은 이번에 수행하지 않았다. 새 코드를 Git에 반영한 뒤 서버에서 pull하고 API를 재시작하면 된다. DB 마이그레이션·env 수정·Firebase/S3 재배포·의존성 추가는 필요 없다.

서버 적용 후 승인된 테스트 고객으로 번호 등록 → 한 번호 삭제 → GET/재로그인 → 다른 번호와 기존 동의 유지 → 두 번호 삭제를 확인한다. 시험을 위해 기존 동의 이력을 초기화하지 않는다. 인계 당시 자료와 회원 현재값의 구분도 화면에서 확인한다.
