# 앱 전달 — 반납 완료 후 90일 채팅 보관 종료

작성일: 2026-11-06. 대상: 고객 앱·관리자 앱의 채팅 목록/화면·알림 담당자. **04:08 UTC 서버 반영·일일 자동 정리 활성화 완료**. 최초 대상/삭제/실패는 0건이며 상세 검증 범위는 [서버 결과](chat-retention-server-result-2026-11-06.md)를 따른다.

## 보관 기준

실제 반납 완료 후 90일이 지난 예약 채팅은 매일 발리 04:15 정리 대상이다. 예정 반납일이 아니라 실제 완료 시각이 기준이며, 90일 경과 후 배치에서 정리한다. 실패·잠금 경합·중단 시 후속 실행에서 재시도하며, 누락분은 서비스 복구 후 보충 실행될 수 있다. 해당 예약방의 메시지·읽음·연결 푸시 이벤트가 함께 정리되고, 과거 문의에서 그 예약방으로 이어진 메시지도 포함된다.

렌트·예약·결제 이력은 계속 표시한다. 진행/연체·취소/거절/만료 예약과 일반 문의방·다른 예약방은 이 정책으로 삭제하지 않는다.

## 앱 처리

- callable 이름·입력, REST API·Firestore 조회 경로·Auth·App Check는 유지한다. 별도 활성화 값이나 새 키를 앱에 추가하지 않는다.
- 채팅 목록의 방 문서 삭제 이벤트를 반영해 해당 항목을 제거한다. 이미 열린 방이 삭제되면 하위 구독을 정리하고 메시지 화면을 종료/안내 상태로 전환한다.
- 삭제된 방의 `ensureBookingChat`은 `not-found / CHAT_NOT_FOUND`다. 보관 종료 안내를 표시하고 같은 예약으로 방을 자동 재생성하거나 무한 재시도하지 않는다. `BOOKING_CHAT_SYNC_PENDING`의 일시 재시도와 구분한다.
- 과거 푸시/알림에서 진입해 방이 없으면 최신 상태를 확인하고 사용할 수 없는 채팅임을 안내한다. 알림함 이력을 렌트 취소·환불로 해석하지 않는다.
- 사라진 방의 로컬 메시지 캐시·목록·읽지 않은 수를 갱신한다. 서버 정리가 기기에 남은 캐시 파일을 직접 삭제하는 것은 아니다.
- 명시적 `CHAT_NOT_FOUND` 또는 목록에서 방 제거가 확인되면 읽음/열기 요청을 반복하지 않고 방 종료 상태로 처리한다. 네트워크·인증·권한 오류 전체를 보관 종료로 해석하지 않는다. 하위 구독은 부모 방 삭제 후 읽기 거절을 받을 수 있으므로 기존 인증 상태·방 목록·ensureBookingChat 결과로 구분하며, 정확한 SDK 오류 이벤트는 공동 시험에서 확인한다.

앱은 서버 전용 삭제 표시를 조회·수정하거나 Firestore에 방을 직접 다시 만들지 않는다.

## 공동 시험 항목

1. 목록에 보이던 방의 삭제 이벤트와 열린 화면 종료 처리.
2. 과거 알림 진입·앱 재시작·오프라인 캐시 뒤 재접속 처리.
3. 보관 종료된 예약의 CHAT_NOT_FOUND 안내 및 자동 재생성/무한 재시도 방지.
4. 기존 렌트 이력 유지, 다른 예약·진행 채팅·일반 문의 정상 사용.
5. 읽지 않은 수·읽음 처리와 고객/관리자 권한 오류 구분.

서버 격리/에뮬레이터 검사 성공과 실제 앱 화면·실기기 캐시 검증을 구분한다. 현재 SQL 계획의 대상 0건 확인은 실제 보관 만료 방을 기기에서 시험했다는 의미가 아니다. 공동 시험에 실제 고객 메시지를 임의로 생성/삭제하지 않는다.
