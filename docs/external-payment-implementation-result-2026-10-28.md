## 설정과 서버 반영

새 설정과 `.env.example`의 기본값:

```dotenv
NADREE_RESERVATION_PAYMENT_METHOD=EXTERNAL
NADREE_PAYPAL_CHECKOUT_ENABLED=false
```

두 값은 비밀값이 아니며 07:22에 `.env` 중복 없이 명시된 값과 새 프로세스의 환경변수, 실제 API 조회 결과가 일치함을 확인했다. 기존 PayPal 자격증명·환경·판매자·웹훅 설정은 지우지 않았다. DB 컬럼·테이블·인덱스·마이그레이션·새 의존성·Firebase 배포는 필요하지 않다. 기존 JSON을 사용하므로 새 예약 행 이외의 데이터 이전은 없다.

사용자 승인으로 07:03 최초 반영에 1회, 별도 env 반영 요청에 따라 07:22에 1회, 최신 업데이트 요청으로 07:50에 1회 재시작했다. 이번 최신 요청의 재시작은 1회다. 여러 인스턴스를 사용하는 경우 새 정책을 모르는 이전 프로세스와 혼용하지 않는다. 이번 반영에서는 인증 로그인·실제 예약 쓰기·실제 청구·환불·푸시·계정 삭제는 수행하지 않았다. 테스트 계정의 세션도 교체하지 않았다.

기존 `/etc/cron.d/nadree-payment-recovery`는 완료 캡처만 조회 정산하는 작업이다. 전체 payments 작업과 구분해 보존했고 cron·timer 등록/중단/실행 명령을 수행하지 않았다. 기존 환불에 필요한 검증·실행 코드도 보존했다.
